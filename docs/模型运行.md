# 在 NVIDIA 平台本地生成

当前生成器针对从 Hugging Face 下载的完整 `Qwen3.5-35B-A3B` 多模态目录，使用 `Qwen3_5MoeForConditionalGeneration`。本项目支持 `transformers>=5.3.0,<6`；启动时检查对应类和 CUDA 能否使用。模型加载和处理器加载均设置 `local_files_only=True`，禁用远程代码、联网取模型和遥测。模型目录应包含配置、分词器、图像处理配置、聊天模板、权重分片及分片索引，不要只放语言模型权重。

模型结构和思考开关见 [Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-35B-A3B)，加载接口见 [Hugging Face 官方文档](https://huggingface.co/docs/transformers/en/model_doc/qwen3_5_moe)。已核对 [Transformers v5.3.0 源码](https://github.com/huggingface/transformers/tree/v5.3.0/src/transformers/models/qwen3_5_moe) 包含该架构；版本下限是本项目选择的兼容范围。

## 环境准备

### 华为A800驱动535的最小安装

已知平台为 Python 3.9.1、NVIDIA A800 80GB、驱动 535.183.01，且没有 torch。当前选择的 Transformers 5.3.0 要求 Python >=3.10，这是第三方模型加载库的要求；仅修改本项目不能在 Python 3.9 中运行它。[官方版本声明](https://github.com/huggingface/transformers/blob/v5.3.0/setup.py)

在指定绝对路径创建独立的 Python 3.10 环境。下面 `/data/envs/qwen35` 换成您有写入权限的目录，环境留在该文件夹：

```bash
conda create --prefix /data/envs/qwen35 python=3.10 pip=25 openssl -y
conda activate /data/envs/qwen35
python -c "import sys, ssl; print(sys.version); print(ssl.OPENSSL_VERSION)"
```

最后一条必须正常显示 Python 和 OpenSSL 版本；若 SSL 导入失败，先定位该错误，不继续安装模型依赖。

进入已经拉取的仓库根目录，安装明确的 CUDA 11.8 版轮子：

```bash
python -m pip install 'torch==2.6.0+cu118' 'torchvision==0.21.0+cu118' --index-url https://download.pytorch.org/whl/cu118
python -m pip install -r requirements-generation.txt
```

CUDA 11.8 的驱动要求允许使用 535 驱动，当前方案无需改动系统驱动。[NVIDIA兼容说明](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html) torch 2.6.0 与 torchvision 0.21.0 的 CUDA 11.8 轮子来自[PyTorch官方版本清单](https://pytorch.org/get-started/previous-versions/#v260)。若该源无法访问，可在可下载软件的环境取回同版本、匹配 Linux/Python 3.10 的轮子，导入后从本地目录安装。

`requirements-generation.txt` 保留您提供的 Pillow 11.1.0、NumPy 2.0.2 版本，固定 Transformers 5.3.0，并补齐 Accelerate、Safetensors 及必要的传递依赖。torch/torchvision 单独从 CUDA 源安装，避免误装 CPU 版。无需 `pip install -e`，因此跳过安装本项目的隔离构建步骤；第一平台的扫描、生成和导出也不再导入历史评审依赖 jsonschema/OpenCC。

检查运行库和真实 GPU：

```bash
python -c "import torch, torchvision, transformers; from transformers import Qwen3_5MoeForConditionalGeneration; print('torch', torch.__version__); print('torchvision', torchvision.__version__); print('transformers', transformers.__version__); print('CUDA', torch.version.cuda, torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"
```

预期为 torch 2.6.0+cu118、torchvision 0.21.0+cu118、transformers 5.3.0，CUDA 11.8 和 True，并能打印 A800。随后填写 `.sh` 中的模型、图片和输出目录，使用单卡和当前解释器启动：

```bash
CUDA_VISIBLE_DEVICES=0 PYTHON_BIN=python bash scripts/generate.sh
```

默认 BF16、SDPA、像素和输出长度配置保持不变，显存是否足够以实际运行时可用空间为准。本地测试没有执行 A800 上的实际模型推理。

使用 Python 3.10 或以上版本。NVIDIA 驱动、CUDA 对应的 `torch` 与 `torchvision` 必须匹配，由目标平台的批准软件源或离线依赖包提供。生成时不会自动安装软件。可以在允许联网的准备环境或公司批准源中安装项目：

```bash
python -m pip install -e '.[generation]'
```

离线机器先准备与其操作系统、Python、CUDA 对应的全部依赖轮子，以及 `setuptools` 等构建依赖。示例命令只访问本地依赖目录：

```bash
python -m pip install --no-index --find-links /本地依赖目录 setuptools
python -m pip install --no-index --find-links /本地依赖目录 --no-build-isolation -e '.[generation]'
```

不要在 Windows 准备环境中直接收集其默认轮子给 Linux 使用。构建离线依赖包时应匹配目标平台，安装后将确切依赖版本留档。本代码的单元测试使用假运行器，没有在当前机器上执行 35B 模型或验证目标 GPU 的显存与速度。

## 填写目录并运行

编辑 `scripts/generate.sh` 顶部的 `MODEL_DIR`、`PRIMARY_IMAGE_ROOT`、`OUTPUT_ROOT` 与 `CUDA_VISIBLE_DEVICES`。`PRIMARY_IMAGE_ROOT` 是含“语种/截图或实拍/图片”的大目录，生成器对扫描清单中的每张有效图片分别生成一次摘要、一次解读、一次菜品推荐。也可以通过环境变量覆盖：

```bash
MODEL_DIR='/data/models/Qwen3.5-35B-A3B' \
PRIMARY_IMAGE_ROOT='/data/images' \
OUTPUT_ROOT='/data/eval/基线一' \
CUDA_VISIBLE_DEVICES='0,1' \
bash scripts/generate.sh
```

脚本设置本地离线环境变量并调用生成命令，不访问评审接口。`OUTPUT_ROOT` 由 CLI 创建运行清单；同一命令再次执行时，成功任务跳过、失败任务重试。每次成功和失败都原子写入独立文件，因此单张图失败不阻止其他样本，摘要失败不阻止同图解读。

一次运行只允许一个生成进程写入。不要对相同运行目录同时执行两份脚本。程序按图逐任务运行，`device_map=auto` 可以在一个进程中跨可见 GPU 放置权重。更换提示词、参数、模型目录、依赖版本或模型配置后，请填写新的 `OUTPUT_ROOT`。`--no-resume` 会重做同配置任务，不能用来混入另一配置。

## 参数与资源

在 `configs/generation.json` 中记录实验条件：

| 字段 | 默认值与意义 |
| --- | --- |
| `dtype` | `bfloat16`；可见 GPU 须支持原生 BF16。否则显式改为 `float16`，新建实验目录 |
| `device_map` | `auto`，由 Accelerate 放置权重；单卡或多卡都保持单进程 |
| `enable_thinking` | `false`，通过聊天模板关闭思考，评估手机直接正文模式 |
| `do_sample` | `false`，贪心解码作为可重复基线；此时 `temperature/top_p/top_k` 不生效 |
| `seed` | `20261012`；每个图片与任务派生稳定种子，重试不会受处理顺序影响 |
| `max_new_tokens` | 摘要 `192`，解读 `2048`，推荐 `1536`；这是令牌截断保护，不等于中文字数限制 |
| `image_min_pixels` | `65536`，处理器最小图像像素预算 |
| `image_max_pixels` | `2097152`，约 2 百万像素；密集菜单的小字可能需要更高预算 |
| `attn_implementation` | `sdpa`，避免默认依赖额外的注意力加速包 |
| `max_memory` | `null`；可指定设备额度，例如 `{"0":"70GiB","1":"70GiB","cpu":"100GiB"}` |
| `offload_folder` | `null`；如需磁盘卸载，填写公司内本地目录，速度会降低 |

图像先按 EXIF 方向转正并转换 RGB，再交给模型自带处理器按像素预算缩放。三个任务使用相同图像预算。修改预算也应创建新实验目录。支持采样实验，将 `do_sample` 改为 `true` 后使用配置中的温度、`top_p` 和 `top_k`；与贪心基线分开比较。即使设置相同种子，不同硬件、计算内核和软件版本也可能产生差异。

官方模型卡列出总参数约 35B、每步激活约 3B。**显存估算必须按总权重计算**：BF16 的 35B 权重约需 70GB（十进制）储存，还要容纳视觉编码器、缓存、激活和框架开销，因此不能按 3B 权重估算。此数值是理论重量级估算，不能保证单张 80GB 卡能够在任意图像和令牌预算下运行。[来源：Qwen 官方模型概览](https://huggingface.co/Qwen/Qwen3.5-35B-A3B#model-overview)

显存不足时，错误会保存到当前任务的 JSON；可先检查空闲显存、可见卡数和其他进程。缩小图像或输出预算会改变实验条件，需新目录。量化模型需要单独验证加载后端与量化配置，当前代码未默认启用量化。

## 保存内容与断点验证

`generation_meta.json` 保存实际配置、完整提示词、运行器与软件版本、模型文件身份及 `settings_fingerprint`。每张图保存：

```text
运行目录/
  run.json
  manifest.jsonl
  generation_meta.json
  samples/
    图片ID/
      summary.json
      interpretation.json
      recommendation.json
```

任务文件有 `status`、`text`、`raw_text`、`raw_output_token_ids`、输入与输出令牌数、延迟、终止原因、提示词版本与指纹、图片 SHA256、稳定种子和错误。`finish_reason=length` 表示未遇到结束令牌而触达上限，应作为截断单独统计；遇到结束令牌，即使刚好到上限，也记 `stop`。输出令牌数包含协议结束令牌。延迟包含图像准备、推理、解码和 GPU 同步，不包含首次权重加载；没有测量服务端并发吞吐。

`raw_text` 使用保留特殊令牌的原始解码。`text` 仅去掉输出末尾的 EOS/PAD 协议令牌，保留正文的所有换行、空白、思考标签、外语和格式。不会截字、重写摘要、删除思考正文、修正事实或补结构。因此测评能观察模型真实的指令遵循结果。

恢复前验证样本身份、设置和图片 SHA256。配置、分词器和聊天模板等小文件计算 SHA256；大权重记录名称、大小和修改时间，不逐字节哈希。**本地模型目录须在实验期间保持不可变**。记录元数据不能排除恶意修改后恢复相同大小和修改时间；若需要严格权重追溯，可在内部环境独立计算完整分片 SHA256 并留档。模型配置、依赖或提示词变化会拒绝向旧目录继续写入。

生成脚本没有 API 调用；评审接口的具体连接待提供后在第二平台的独立 evaluate.py 中配置。

本次两个数据集的工作目录独立保存在 OUTPUT_ROOT/primary 与 OUTPUT_ROOT/menu_reference，用于断点与原始运行记录。运行后自动在 OUTPUT_ROOT/handoff.json 汇总交接数据，包括两套数据分组、三任务原文、推荐要求、实际提示词、明确输入的汇率、原图完整字节和 SHA256。原图未再次压缩或修改。

跨平台只复制 handoff.json 和仓库根目录的 evaluate.py 两个文件。第一平台工作目录、图片目录和模型均不需要移交；第二平台无需填写第一平台路径或安装生成依赖，直接运行：

```bash
python evaluate.py handoff.json
```

默认输出平铺的 results.json 和 report.html，两个测试集在文件内部独立汇总。GPT 接口未接入时另外准备 reference_requests.json，并把语义指标标为未测。完整流程见 README。
