# 模型基础能力与细粒度评测方案

日期：2026-10-21。状态：方案设计，尚未开展跨场景新实验。本文的演示输出均为人工构造的判分示例，不是当前模型的实测结果。

## 1. 目的与结论

要回答的问题是：**用户自然地上传图片或提问时，当前模型能否判断任务、读懂内容、保留关键信息，并给出有依据的总结、解读、推荐或常用语？**

建议采用“领域 × 任务 × 输入难度”的测试集，用**人工核定事实和规则计算**评分。结果按能力分别报告，不以模型自行给出的印象分作为结论。

首要指标为：分流正确性、事实支持率、关键事实覆盖率、关键错误率、推荐约束满足率、说明与方案一致率。长度、截断、追问和外部知识使用情况同时记录。已有45例只覆盖菜单、推荐及票务；药品、化妆品、食物标签、路牌、开放分流均尚未实测。

| 先看什么 | 回答的能力问题 |
|---|---|
| 分流与必要追问 | 是否理解用户需求，信息不足时是否知道问什么？ |
| 事实支持率 | 说出的内容有多少能找到正确依据？ |
| 必需/关键事实覆盖率 | 总结是否漏掉用户真正需要的信息、警示和例外？ |
| 关键错误案例率 | 是否把否定、对象、单位或决定结论的条件说错？ |
| 推荐与解释一致性 | 方案是否满足约束，解释是否与实际方案一致？ |
| 常用语任务可用率 | 推荐的表达是否保留用户意图，能否直接用于沟通？ |

## 2. 测试条件：先测模型，再测辅助系统

| 条件 | 模型获得什么 | 评价什么 | 是否进入基础能力主表 |
|---|---|---|---|
| M0 原始模型 | 自然用户输入、图片、固定产品提示词；没有纠错反馈 | 无检索、无检查程序帮助时的第一次可见回答及任务选择 | 是，默认主结果 |
| M1 给定知识 | M0输入＋预先冻结的相关资料；没有纠错程序 | 模型能否正确理解和使用可靠资料 | 单列；不能当作闭卷知识能力 |
| M2 允许检索 | 相同输入＋固定搜索/检索工具、次数与时间额度 | 能否找到正确资料，并据此作答 | 单列；包含检索能力 |
| M3 辅助系统 | 加入规则纠错、工具计算或失败重试 | 模型与工程整体表现 | 单列；不得替代M0 |

记录首次回答、每次反馈后的模型回答、程序直接修改的内容、最终显示内容。分别计算“首次做对率”“模型收到反馈后的纠正率”“程序直接修正率”，不能只保留最终答案。反馈纠正率的分母为**首次失败且实际收到反馈的案例**；未纠正、超时、无回复仍留在分母，同时报告重试次数。

同一条件再做成对输入：真实图片 vs 人工核对的完整转写。图片错、转写对，提示视觉识读环节有问题；两者都错，提示后续理解存在问题。该结果用于定位，不能将全部差值简单视为OCR误差。

M1提供“已找好的相关资料”也可能提示领域和任务，因此其理解增益优先在给定正确任务的执行子实验中比较；若做端到端比较，必须注明输入提示也发生了变化，不能把全部增益归因为知识补充。资料中加入相似但不适用的产品/地区版本作为干扰，检查是否匹配对象。

## 3. 数据集怎样分类

领域：药品、化妆品、食物标签、路牌、菜单，另设其他/未知、多对象、图像不可辨认。任务允许多个标签：归纳整理、内容解读、推荐组合、常用语、追问/无法判断。**识别出“菜单”不等于用户要求推荐菜品。**

| 领域 | 归纳整理要保留什么 | 解读要检验什么 | 推荐与常用语要检验什么 |
|---|---|---|---|
| 药品 | 药名、规格、适用对象、用法原文、警示、否定和例外；按问题选择必需项 | 原文允许得出的结论、未知信息和需查证的知识是否区分；剂量、单位、频次、年龄限定不能改写错误 | 推荐测试以信息不足时追问、转介和拒绝无依据替换为主；实际用药方案须另建专家审核任务。常用语需忠实传递药名、过敏、症状及请求，不擅自下诊断 |
| 化妆品 | 产品名、成分、用法、警示、标注功效与适用限制 | “标签宣称”“资料中的成分作用”“已证实的整品效果”是否被混淆；缺浓度、配方时是否过度推断 | 仅在给定产品属性与偏好下比较；不能由某成分存在推出整品有效或对该用户一定安全。常用语不得添加用户未表达的过敏或功效承诺 |
| 食物标签 | 份量、每份/每100克、热量与单位、营养值、配料、过敏原及可能含有提示 | 换算基准、实际食用份数、配料与营养描述是否正确；不能由缺标注推断不含过敏原 | 约束按给定标签核验；缺少关键证据时询问。常用语要保留过敏/忌口的否定、对象与询问意图 |
| 路牌 | 标志主体、附牌、箭头、时段、单位、车辆对象、例外 | 限制对象、范围、条件及例外有没有读反；国家/地区不明且影响含义时是否追问 | 仅解释已知标志及条件；缺少道路全景时不武断给出通行指令。常用语区分问路、询问限制和要求许可 |
| 菜单 | 菜名、价格、币种、份量、辣度及已明确列出的成分 | 未写价格或辣度时是否保留未知；翻译与推断是否区分 | 菜品存在、数量、预算、已知忌口、份量证据、解释金额一致；常用语忠实表达订餐、换菜、问配料等请求 |

同一领域内安排正常、缺字段、模糊遮挡、数字/单位边界、否定/例外、来源冲突。真实采集样本为主；人工扰动专测“8→18”“mg→g”“可以→不可以”等错误敏感性，扰动结果单列。

## 4. 分流评测：不让用户填写分类标签

用户输入保持自然，例如“一张药盒图片＋帮我看看”“这几个怎么搭配”“这句怎么跟店员说”。系统可按需要选择多个任务，也可请求补充信息。标签和参考答案只给评分端。

先由标注者记录：领域集合、用户已表达的任务集合、缺失但会影响决策的信息、允许的下一步动作。任务不唯一时保存**允许动作集合**，不强造唯一标准答案。例如“这是什么？”可接受识别物品并简述；不能把“未给剂量建议”判成错误。只上传图片且意图不足时，简述已见内容并询问需求可以合格，不能要求猜中用户未表达的心意。

| 指标 | 严格定义与分母 |
|---|---|
| 领域识别 | 单领域报准确率；多领域报精确率、召回率和集合完全匹配率；“其他/未知”作为有效类别 |
| 任务识别 | 对意图明确的样本，以预标注任务集合计算每类及宏平均F1；不将任务歧义样本硬算单标签准确率 |
| 下一步动作正确率 | 执行、追问、保留未知或说明不能判断，是否落在人工核定的允许动作集合中；分母为全部样本 |
| 必要追问召回率 | 应追问且实际提出有关问题的案例÷所有应追问案例；只问“还有吗”不算补齐必要信息 |
| 多余追问率 | 信息已足够却阻断任务、追问无关或已知信息的案例÷所有无需追问案例 |
| 关键漏分流率 | 未识别某高风险领域/必需处理动作的案例÷该类真实案例；按领域单列 |

输出混淆矩阵和每类样本数。分别跑“自然分流端到端”和“评测器指定正确任务”的诊断实验。前者反映实际表现，后者排查分流后的能力；后者的任务标签不能泄漏到前者。端到端成功必须分流合理且后续回答合格，不能仅对成功分流子集报高分。

若产品有独立路由模块，直接记录它输出的领域、意图和下一步动作。若模型只输出自然语言、没有显式分类，则先评价**可观察到的下一步动作**；另设固定格式的分类探针作为诊断实验。不能从一个回答的主题反推“内部路由准确率”，也不能把探针提示后的准确率冒充原产品的自然分流表现。

## 5. 评分答案怎么建立

每道题不用一段唯一参考答案，而用一张**事实与规则清单**：

| 字段 | 内容 |
|---|---|
| 输入证据 | 原始图片及哈希、人工转写、区域/行号；对不可读区域明确标未知 |
| 来源事实 | 拆成“对象—关系—值—单位—否定—适用条件”的原子事实，每条有证据位置 |
| 必须覆盖的事实 | 与用户请求有关的必需项；关键项另标critical，发布前冻结 |
| 可以不提的事实 | 与当前问题无关的背景；不能因没复述整篇而扣分 |
| 外部知识 | 来源、文档版本、适用地区、型号/产品规格、检索日期、段落；不能由标注者记忆代替 |
| 允许推理 | 依据哪些事实、通过何种计算/规则可得出哪些结论，含边界与单位 |
| 未知与禁推断 | 如“未提供香精信息”“未给完整配料”；不能把缺证据当作否定事实 |
| 决策规则 | 可选组合、预算、合法数量、优先目标、需追问条件、允许动作集合 |

两名独立标注者先在**未看模型答案时**建立清单，分歧由第三人裁定；药品与高风险解释须有相应专家审核。新增且未列入清单的模型说法，仍逐条核验，不能因“不在参考答案”直接判错。测试集中发现标准有误时，修订版本并对所有被比较模型重算。

至少记录事实标签的一致率及分歧类型；类目适用时报告Cohen's κ或Krippendorff's α，并同时给原始一致率与类别分布。未裁定项暂不计已判定事实分，但必须报告未裁定数量，不能隐藏。

## 6. 归纳整理与AI解读：主要细粒度指标

先把**模型实际表达的内容**拆成独立可核验主张；同一事实重复表达只计算一次。每条标为：有证据支持、与证据矛盾、无法由允许证据确认；有争议则暂列待裁定。部分正确的复合句必须拆开，不给模糊的“基本正确”。

原子事实支持思路参考[FActScore](https://aclanthology.org/2023.emnlp-main.741/)；本项目额外加入关键覆盖、数字/限定词与分流指标。这是项目设计，不是照搬论文分数。

| 指标 | 计算方法 | 谁来判 |
|---|---|---|
| 事实支持率 | 有证据支持的去重主张数÷已裁定的全部去重事实主张数；矛盾与无证据均留在分母 | 数字/字段用规则；语义由证据定位＋双人标注 |
| 事实矛盾率 | 与来源或允许知识直接冲突的主张数÷已裁定事实主张数 | 同上 |
| 无依据扩展率 | 允许证据无法支持的主张数÷已裁定事实主张数；外部真实但不该混入的知识另计越界，不等同事实为假 | 同上 |
| 必需事实覆盖率 | 正确传达的必需事实数÷该题预标注必需事实数；错误提及不算覆盖 | 与冻结清单一一匹配；允许同义表达 |
| 关键事实覆盖率 | 正确传达的critical事实数÷该题critical事实数 | 对剂量、否定、例外等单独核对 |
| 关键错误案例率 | 出现至少一个预定义关键错误的案例÷该风险层全部案例；每个错误仍保存证据和类别 | 规则＋专家复核 |
| 数值与限定条件正确率 | 正确的数值-单位-对象-范围-时段/频次/否定组合÷所有应核验组合；只对数字相同不能算对 | 单位规范化与精确规则，语义范围人工核验 |
| 原文/知识/推断区分正确率 | 应标明归属的主张中，归属和条件均正确者÷应标明主张数 | 核对证据与任务协议 |
| 解释推理正确率 | 预标注解释结论中，前提、规则与结果均正确的结论数÷必需解释结论数；无依据的因果结论同时记无依据扩展 | 可计算项用规则；其余专家标注 |
| 未知处理 | 分开报：证据不足时武断回答率；证据充分时整题拒答率；可回答项完成率 | 先标注每字段是否可回答，再核对输出 |

如果模型不作任何事实陈述，事实支持率为N/A，不能给100%；必需事实覆盖按0处理，并记录空回答/拒答。题目确实无需某指标时为N/A，报告有效分母，不把N/A换成满分。不能靠少说、全拒答或只复制安全提示刷高正确率。

“归纳整理”重点看**是否选对关键事实、压缩时保留限定条件**；“AI解读”还要看**是否能在条件成立时解释含义、区分原文与外部知识、指出不能推出的结论**。不能只测逐字抽取，也不能把“是否说得像专家”当作能力。

同时给每条主张标注“依据原文／依据外部资料／推断”。来源忠实度与外部事实真实性分开：例如原图没写“不含香精”，即便另查官网证实，也不能算作图片本身已提供的信息。外部事实尚未核实时记待裁定或无证据，不能自动当真；“无依据”也不直接等于现实世界必然为假。

针对总结中对象、关系、条件和跨句推理的错误分类，可参考[FRANK](https://aclanthology.org/2021.naacl-main.383/)；这些来源支持错误分解，不能替代本项目的领域标注。

## 7. 推荐组合与常用语

### 推荐组合

1. **约束满足率**：满足全部必需条件的方案÷全部推荐任务；缺省不推断用户偏好。分别列菜品存在、数量合法、预算、已给忌口、可用性、说明一致性。
2. **金额/数量核算**：价格用最小货币单位整数计算；小计、费用、总价、余额逐项核对。营养换算须固定每份/每100克基准。
3. **说明一致率**：正确说明方案属性、金额与条件的说明主张÷所有相关说明主张。F03式“方案48、解释78”必须在此失败。
4. **目标达成**：只有任务明确目标且候选/约束完整时，才用穷举或约束求解器得到可行集合和最优值。报可行率与目标差距；不能将“越便宜越好”当所有推荐的默认目标。
5. **偏好质量**：无唯一最优解时，用独立用户/专家的匿名成对比较，允许平局，预定比较维度并交换展示顺序；单独报告偏好胜率，不与客观约束混分。无份量数据时不评价“保证够吃”。

没有可行解时，“指出不可行并询问是否放宽某条件”可为正确动作。不能为了凑方案放宽过敏、预算等条件。过敏项仅能评价给定证据中的成分信息，不代表现场食用安全。

### 常用语推荐

每题预标注沟通意图、必须传达的语义槽位和禁止改写的条件，允许多种自然表达。先核对：**对象、动作、请求/断言、否定、数量、过敏/偏好、礼貌强度**；再评语言自然度。

- 必需槽位完整率＝正确传达槽位÷必需槽位；否定反转或把询问改断言另报关键错误。
- 任务可用率＝意图与关键槽位均正确且目标语言可理解的案例÷所有常用语任务。
- 新增事实率＝加入用户未表达的事实主张数÷全部事实主张数。
- 自然度采用双语评审0/1/2锚点：无法理解或语用错误／能用但有明显不自然／自然且语境合适。此项是人工判断，保留分歧，不称为纯客观准确率。

例如“请帮我问这道菜有没有虾”应保持询问；改成“这道菜没有虾”即使很流利也失败。BLEU/ROUGE等表面相似度只作辅助手段，不能将不同措辞的正确表达判错；总结质量应结合内容和人类标注，相关研究可参考[SummEval](https://aclanthology.org/2021.tacl-1.24/)。

## 8. 什么时候需要外部知识

| 问题类型 | 证据边界 | 实验怎么做 |
|---|---|---|
| “把包装上写的内容总结一下” | 图片/原文足够；额外常识须分栏，不得改写成标签事实 | M0，主测来源忠实度与覆盖 |
| “这个标志在当地什么意思”“成分名称是什么” | 可能需要地区规则、术语或规范资料 | M1先检验给定知识后的理解，M2再测查找能力 |
| “适合我吗”“能否一起使用” | 通常还缺个人条件、浓度、剂型或完整场景 | 标注必需追问与知识来源；没有证据时不能把断言当正确答案 |

评分端始终可访问核定证据，模型是否能访问由M0/M1/M2条件控制。M0中原文外的知识主张单独核实和归类，不能把真实常识全部判为“幻觉”，也不能让常识覆盖原图的限定条件。

外部证据按产品/场景的**地区、版本、规格、时间**匹配，冻结内容快照与哈希；主观营销文案只能证明“厂商如此宣称”，不能作为疗效或安全性的充分证明。资料冲突时预标允许的冲突说明/追问，不强行指定一个未经核定的结论。

来源例子：美国药品可使用[DailyMed](https://dailymed.nlm.nih.gov/)中与具体产品匹配的标签，并核实其审批状态；收录不等于已获批准，见[FDA标签说明](https://labels.fda.gov/)。欧盟化妆品可用[CosIng](https://single-market-economy.ec.europa.eu/sectors/cosmetics/cosmetic-ingredient-database_en)核对成分资料，但其中出现不等于许可或整品功效证明。英国路牌可依据[官方Traffic signs](https://www.gov.uk/guidance/the-highway-code/traffic-signs)；其他地区另选适用官方资料，不能跨地区套用。

M2额外报告：关键证据召回率@K、来源有效率、引用支持率、需要引用的结论覆盖率、过期资料率和查询成本。引用必须支持对应结论且对象/版本正确，“有链接”不算支持。引用精度与覆盖分别评估的思路可参考[ALCE](https://aclanthology.org/2023.emnlp-main.398/)。

## 9. 评分系统如何落地

流程：**冻结测试集和证据 → 保存原始输入/输出 → 提取待核验主张 → 规则与证据核验 → 人工裁定语义/专业项 → 计算分项指标 → 抽查评分错误 → 输出分类结论。**

| 评分层 | 可以做什么 | 不能据此做什么 |
|---|---|---|
| 确定性程序 | 检查字段、数字、单位、预算、方案可行性、长度、结束原因与已核定槽位 | 仅靠关键词判断全部语义和药品适用性 |
| 人工/领域专家 | 建金标准、定位证据、判同义、否定范围、因果与专业含义，裁定分歧 | 无证据凭个人印象给“总体90分” |
| 辅助模型 | 提议拆分主张、寻找证据、标出疑似冲突，减少人工检索量 | 自己生成标准答案再给自己打分；以其输出直接当金标准 |

辅助评分器先在人工裁定样本上校准，报告逐类错误检出精确率/召回率、漏掉关键错误的比例、改写和交换顺序后的稳定性。校准通过后可用于低风险批量筛查，随机抽查“通过”结果，并复核全部高风险和冲突结果。多个模型投票不是独立真值。[LLM裁判研究](https://arxiv.org/abs/2306.05685)记录了位置、长度与自偏好等偏差，因此模型评分只能作为经校准的辅助证据。

给评分器做故障注入：数字换错、单位错、否定反转、删关键警示、交换对象、移除附牌、虚构引用、流畅但错误、冗长重复、整题拒答。记录它是否检出**预先知道的错误**；也加入正确的同义改写，检查是否误杀。

不建议首版使用加权总分。若展示必须有分数，按某个已明确定义的比例×100显示，同时展示分子/分母、关键错误数和适用范围；跨域总分的权重、门槛必须在实验前冻结。关键错误不能被流利度、字数或其他满分抵消。

## 10. 长度、截断与稳健性

分开记录用户可见文字字符数、完整菜单/卡片文本量、每次模型输出tokens、输入tokens、累计tokens、上下文/输出配置和API结束原因。工具参数也属于模型输出，不等于用户需要阅读的字数。缺字段记“未记录”，不能当0。

- **长度合规率**：满足任务事先规定的字符/句数区间的案例÷有长度约束案例。没有长度要求只描述分布，不事后定300字为失败线。
- **输出额度截断率**：API标记为长度上限结束的调用÷全部调用；保留每次结束原因，不能将工具调用结束当截断。
- **语义完整率**：即使API正常结束，必需事实是否仍完整；“正常stop”不能证明没漏内容。
- **界面显示完整率**：渲染后用户实际能访问的必需内容÷应显示内容；独立于模型测试。
- **受限长度下的质量**：同一批任务，在至少3档事先固定的输出预算下，比较事实支持率、关键覆盖和截断；另设长输入位置测试与上下文超限处理。

模糊、旋转、不同排版、同义提问、语言变体及否定最小改动使用成对测试。对于温度0也记录复跑稳定性；选固定子集复跑3次，报告跨次差异，不能只挑最好一次。

## 11. 六个判分示例：展示怎样避免“凭感觉打分”

以下均为构造题，**不是医学、交通或产品使用建议，也不是模型实测**。

| 场景/任务 | 冻结输入与评分依据 | 故意构造的输出 | 可复核的判分 |
|---|---|---|---|
| 药品标签/总结 | 虚构标签：仅外用；避免接触眼睛；儿童须在成人监护下使用。三项均为必需项，后两项为关键项 | “仅供外用，避免接触眼睛，儿童可自行使用。” | 3个主张中2个支持、1个矛盾：支持率2/3；覆盖2/3，关键覆盖1/2；出现关键错误。字句通顺不加回事实分 |
| 化妆品/解读 | 虚构包装：保湿；成分含X；未提供X浓度及刺激性测试。X无真实物质指代 | “含X，因此已经证实不会刺激。” | 拆为“含X”和“已证实不会刺激”：前者支持、后者无证据；支持率1/2；属于无依据结论。未提供浓度不能推断整品效果 |
| 食物/换算 | 虚构标签：每份30克，每份120千卡；本次吃60克，问摄入热量 | “摄入120千卡。” | 金标准120×60/30＝240千卡；换算结果错误，任务失败。不是字符串相似度问题 |
| 路牌/解释 | 仅为文字逻辑题：限制时段“8–18”；附注“公交除外”，问哪些车辆受限；不涉及任何地区真实通行规则 | “8–18所有车辆都受限。” | 保留时段，但丢失公交例外；必需事实2条只覆盖1条，关键例外覆盖0/1；结论过度扩大 |
| 菜单/组合 | 鸡饭14、沙拉8、饮料4；预算24，无其他要求 | “鸡饭＋沙拉＋饮料，共24。” | 程序算出26；预算和金额说明同时失败。组合存在且数量合法不能掩盖这两项错误 |
| 常用语/分流 | 用户：“帮我用英语问这道菜有没有虾。”允许任务为常用语/翻译，必需槽位：询问、这道菜、虾 | “This dish contains no shrimp.” | 对象和虾保留，但把询问改成无虾断言；槽位覆盖2/3，任务可用性失败，存在无依据扩展。用户未要求推荐，触发推荐也记分流错误 |

这些指标有不同分母，不能把表中比例直接平均成“总体能力分”。

## 12. 实验规模、统计与交付

建议先用60条独立校准案例修订标注规范与评分器，随后冻结规范；另建200条盲测主案例（五领域各40个不同来源对象）及50条自然分流/多对象/模糊需求案例。任务类型按领域实际适用性分层，不强迫每个药盒都做用药推荐。此规模用于发现能力缺口，不足以证明罕见高风险错误已消失。

开发集、校准集、盲测集按产品/菜单/标志来源和模板家族隔离；同一产品换语言、图片裁切或仅改价格仍属于同簇，不能跨集泄漏。各场景样本数与真实业务分布均记录，既报分层宏平均，也可另报固定业务权重平均；不把平衡采样总体直接称为线上准确率。

主实验事先登记模型版本、完整提示词、任务定义、工具权限、知识快照、输出上限、温度、超时、拒答和错误处理、聚合方式及采样日期。保留运行异常；主表的端到端成功率不能删掉无响应或解析失败样本；另报排除这些基础设施异常后的条件结果。

每个比例给出分子/分母和95%置信区间。独立案例可用[Wilson区间](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)；同一来源的多问、多图片及多事实存在相关性，按来源簇进行bootstrap，不能把120个重复菜名视为120个独立试验。对比模型或M0/M1时用同题配对差值和按簇重采样，报告区间，不只报涨了几个点。

参考尺度：在独立同分布假设下，10/10成功的Wilson 95%区间约为72.2%–100%，不能证明普遍100%。这些假设对现有重复模板并不充分，旧实验只应作样本内描述。零次关键错误也需给上限；大样本零失败时“约3/n”的95%单侧上界仅是近似，正式报告选定精确方法。

首版交付四张主表：①各场景分流与必要追问；②M0事实支持/关键覆盖/关键错误；③推荐及常用语细项；④M1、M2、M3相对M0的增益与成本。附每例“输入—原始输出—问题证据—结论”，同时保留失败、部分正确和无问题案例。

最终结论按故障定位表达：给定正确转写仍错→理解/推理缺口；给定可靠资料变对→知识获取或知识使用可改善；正确任务标签下变对→分流缺口；原始模型错而程序改对→工程补救有效。**这些是后续实验要检验的解释，当前旧样本不能替代验证。**

## 13. 下一步实施顺序

1. 冻结任务与分流标签、事实字段、关键错误定义和证据来源；用校准集完成双人标注规范。
2. 实现可确定判定的字段/数字/预算/单位/长度评分，建立语义与专家裁定队列；先验证评分器能检出植入错误。
3. 锁定新盲测集，先跑M0与图片/转写配对；再跑M1定位知识因素，按需求增加M2与M3。
4. 输出分项指标、区间与失败案例，再决定优先调提示词/分流、工程检索，还是针对稳定的语义与推理错误训练模型。

本方案不预设“工程就够了”或“必须微调”。用上述对照，才能判断当前模型的基本能力与辅助系统分别贡献了什么。
