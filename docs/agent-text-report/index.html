分数怎么打

翻译：满分 100

菜名含义 40 分 + 项目完整 20 分 + 价格与币种 20 分 + 未知信息处理 20 分。

项目完整要求不漏项、不多项；其余三项按正确比例给分。例如 6 项中 1 项辣度误判，扣 20÷6≈3.33 分。

推荐：满分 100

菜品在菜单内且数量为正整数 30 分 + 满足已给忌口 30 分 + 不超预算 40 分。

每项满足得全分，否则得 0 分。方案只要超预算，即使其他两项正确，也只能得 60 分。

准确率看“多少项正确”，评分看“检查项得了多少分”。推荐合规不代表符合个人口味；100 分也不代表说明文字完全正确。F03 的组合实际为 48 欧元，首次说明却写成 78 欧元，这个文字错误未计入方案分。

Token 截断：模型是否因额度用完而停止

Token 是模型切分文本后的计量单位，与汉字数不一一对应。输出截断指达到单次输出额度后被迫停止；本报告以接口日志的 finish_reason=length 为判据。

指标定义本次结果
单次输出上限每次模型调用允许生成的最大 token 数；不是输入上下文上限。4,096 tokens
单次实际输出长度接口记录的输出 token 数，包含自然语言或工具调用参数。平均 216.3；最大 411，约占上限10.0%
输出截断率因长度上限结束的调用数 ÷ 全部129次调用。0/129（0%）
调用结束方式正常输出工具参数，或自然结束回复；这两类均不算长度截断。工具调用结束81次；自然回复结束48次

45个任务共调用模型129次，累计输出27,898 tokens；平均值为27,898÷129。累计值不能与单次4,096上限比较。程序生成的最终回复没有另行统计token数。

结论：本批短回复未发现 token 上限截断。回复变短主要来自程序整理。长文本是否截断、页面是否隐藏文字、输入上下文是否被裁剪，本批均未验证。

5. 结论

  1. 基础翻译可用。本批 120 项菜名含义均正确，但未知辣度需要按来源检查。
  2. 优先完善工程。预算校验、失败重试和程序计算金额已能纠正本批错误；还需核对说明文字与方案是否一致。
  3. 暂不优先做模型微调。SFT 是用正确示例继续训练模型。本实验未做微调对照，尚不能证明它比工程校验更必要，也不能证明工程能解决所有问题。

适用范围：固定开发样本，20 张菜单重复使用 6 类菜品、18 种原文表达；结果不代表开放菜单准确率。下一步用未参与开发的新菜单和长文本复测，再决定是否调算法或做 SFT。
